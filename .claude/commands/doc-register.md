# /doc-register コマンド

Issue/Feature完了時に、成果物をカテゴリ別の既存ドキュメントに追記・統合します。

## 実行手順

あなたは以下の手順で `/doc-register` コマンドを実行してください：

### 1. Issue情報取得

Issue番号から以下の情報を取得：
- Issue本文（ユーザーストーリー、受入基準）
- ラベル（category, scope判定用）
- 関連PR情報
- 親Issueの場合は子Issue一覧

```bash
gh issue view ${ISSUE_NUMBER} \
  --json number,title,body,labels,assignees,state,closedAt \
  > /tmp/issue-${ISSUE_NUMBER}.json

gh pr list --search "Fixes #${ISSUE_NUMBER}" --state all --json number,title,mergedAt \
  > /tmp/pr-${ISSUE_NUMBER}.json
```

### 2. スコープ・カテゴリ自動判定

- **スコープ判定**: `dev-reports/feature/issue/{issue_number}/` のプロジェクト言及をカウント
  - expertAgent言及が多い → `scope=expertAgent`
  - ラベル `project:myVault` → `scope=myVault`
  - タイトルに「プロジェクト全体」 → `scope=global`

- **カテゴリ判定**: ラベル・タイトルから判定
  - `architecture`, `tech-debt` → `category=arch`
  - `feature`, `enhancement` → `category=spec`
  - `ops`, `deployment` → `category=ops`
  - `documentation`, `onboarding` → `category=rule`

### 3. dev-reports情報抽出

`dev-reports/feature/issue/{issue_number}/` から以下を抽出：
- `design-policy.md`: 設計方針、アーキテクチャ
- `work-plan.md`: 実装詳細
- `test-report.md`: テスト結果

```python
dev_reports_dir = Path(f"dev-reports/feature/issue/{issue_number}")

if dev_reports_dir.exists():
    design_policy = (dev_reports_dir / "design-policy.md").read_text()
    work_plan = (dev_reports_dir / "work-plan.md").read_text()
    test_report = (dev_reports_dir / "test-report.md").read_text()
```

### 4. ターゲットファイル判定

- ベースディレクトリ決定:
  - `scope=global` → `docs/{category}/`
  - `scope={service}` → `{service}/docs/{category}/`

- 既存ドキュメントとの類似度計算
  - 類似度 > 0.6 → 既存ドキュメントに追記
  - 類似度 < 0.6 → 新規ドキュメント作成

```python
if scope == "global":
    base_dir = f"docs/{category}"
else:
    base_dir = f"{scope}/docs/{category}"

# 既存ドキュメントとの類似度計算
existing_docs = list(Path(base_dir).glob("*.md"))
target_file = find_most_similar_or_create_new(issue_title, existing_docs, base_dir)
```

### 5. セクション生成

以下の構造でセクションを生成：

```markdown
## Issue #{number}: {title}

**ステータス**: ✅ 完了
**完了日**: {closedAt}
**担当者**: {assignees}
**関連PR**: #{pr_number}

---

### 📋 概要

{dev-reports/design-policy.md から抽出}

### 🎯 ユーザーストーリー

{Issue本文から抽出}

### ✅ 受入基準

{Issue本文から抽出}

### 🏗️ アーキテクチャ

{dev-reports/design-policy.md から抽出}

### 🔧 実装詳細

{dev-reports/work-plan.md から抽出}

### 🧪 テスト結果

{dev-reports/test-report.md から抽出}

### 📦 関連子Issue（親Issueの場合）

- ✅ [Issue #{child_num}](../../issues/{child_num}): {child_title}
- ...

---

_最終更新: {datetime.now()} by /doc-register_
```

### 6. 既存ドキュメントに追記

- ターゲットファイルを読み込み
- セクション挿入位置を決定（ファイル末尾、または類似セクションの後）
- セクションを挿入
- ファイルを保存

```python
# ターゲットファイル読み込み
target_path = Path(target_file)
if target_path.exists():
    existing_content = target_path.read_text(encoding='utf-8')
else:
    # 新規ドキュメント作成
    existing_content = create_new_document_header(category, issue_data)

# セクション挿入
updated_content = existing_content + "\n\n" + new_section

# 保存
target_path.write_text(updated_content, encoding='utf-8')
```

### 7. Gitコミット

```bash
git add {target_file}
git commit -m "docs({scope}/{category}): update {target_file} - Issue #{issue_number}

Issue #{issue_number}: {title}
- Scope: {scope}
- Category: {category}
- Target: {target_file}
- Section: {section}

Generated by /doc-register

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>"
```

## 配置ルール

| スコープ | 配置先 | 用途 | 例 |
|---------|-------|------|-----|
| global | `docs/rule/` | プロジェクト全体のガイドライン | 開発フロー、Git戦略 |
| global | `docs/arch/` | プロジェクト全体のアーキテクチャ | システム構成図、DB設計 |
| global | `docs/spec/` | プロジェクト横断機能 | ユーザー管理、決済 |
| global | `docs/ops/` | プロジェクト全体の運用 | リリース手順、監視 |
| {service} | `{service}/docs/arch/` | マイクロサービス固有設計 | LangGraph設計 |
| {service} | `{service}/docs/spec/` | マイクロサービス固有機能 | Job Generator |
| {service} | `{service}/docs/ops/` | マイクロサービス固有運用 | デプロイ手順 |

## 実装例

```bash
# ユーザーからの入力例
/doc-register 152

# あなたの実行内容
1. Issue #152の情報を取得
2. スコープ=expertAgent、カテゴリ=spec と自動判定
3. dev-reports/feature/issue/152/ から情報抽出
4. expertAgent/docs/spec/MLOps-Features.md に追記
5. Gitコミット
6. 結果をユーザーに報告
```

## オプション

| オプション | 説明 | デフォルト |
|-----------|------|-----------|
| `--scope <global\|{service}>` | スコープ（global=ルートdocs/, service=マイクロサービス内） | 自動判定 |
| `--category <rule\|arch\|spec\|ops>` | カテゴリ | 自動判定 |
| `--target <ファイル名>` | 追記先ドキュメント | 自動判定 |
| `--section <セクション名>` | 追記先セクション | 自動判定 |
| `--draft` | ドラフトモード（コミットしない） | false |
| `--no-child` | 子Issue自動処理スキップ | false |

## 注意事項

- 自動判定が適切でない場合は `--scope`, `--category` で明示的に指定
- セクション挿入位置が不適切な場合は手動調整が必要
- 親Issueの場合は子Issue情報も自動的に統合される
