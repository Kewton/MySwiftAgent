# 環境変数設定ガイド

**Issue**: #146 - 環境変数の階層的管理機能
**作成日**: 2025-11-09
**対象**: MySwiftAgent 開発者・運用者

---

## 📋 概要

このガイドでは、MySwiftAgentにおける環境変数の階層的管理機能の使用方法を説明します。

### 主な機能

- ✅ `.env`と`.env.local`の階層的読み込み
- ✅ カスタム環境ファイル指定（`--env-file`オプション）
- ✅ 環境変数の優先順位制御
- ✅ 必須変数の自動バリデーション
- ✅ サービスURL自動構成
- ✅ Dry-runモード（`--dry-run`）

---

## 🎯 環境変数の優先順位

環境変数は以下の優先順位でマージされます（数字が大きいほど優先）：

```
4. --env-file で指定されたカスタムファイル（最優先）
   ↓
3. .env.local（worktree固有設定）
   ↓
2. .env（プロジェクト共通設定）
   ↓
1. コード内のデフォルト値（最低優先）
```

### 使用例

```bash
# ケース1: .envと.env.localを使用（通常の開発）
./scripts/unified-start.sh start

# ケース2: .env.localで一部の値を上書き
# .env にある LOG_LEVEL=INFO を .env.local で LOG_LEVEL=DEBUG に変更

# ケース3: カスタムファイルで全ての設定を上書き
./scripts/unified-start.sh start --env-file .env.production
```

## 📁 環境ファイルの配置

### 標準構成

```
MySwiftAgent/
├── .env                # 共通設定（必須）
├── .env.local          # worktree固有設定（任意）
├── .env.example        # テンプレート
└── scripts/
    └── unified-start.sh
```

### Worktree環境での構成（推奨）

```
MySwiftAgent-worktrees/
├── .env.shared         # 全worktree共通設定（実体）
│   └── MSA_MASTER_KEY=base64:Rup6PTJHFJybCSG0sY9a/wtT/wNoEWlu1MfV6nCdhr8=
│
├── main/
│   ├── .env -> ../.env.shared      # シンボリックリンク
│   ├── .env.local                  # worktree固有設定（ポート: 8001-8005）
│   └── myVault/data/myvault.db     # MyVault DB（実体）
│
└── feature-issue-146/
    ├── .env -> ../.env.shared      # シンボリックリンク
    ├── .env.local                  # worktree固有設定（ポート: 8171-8175）
    └── myVault/data -> ../main/myVault/data/  # シンボリックリンク
```

**重要な設計原則**:
- ✅ **`.env.shared`**: 全worktreeで共通の設定（MSA_MASTER_KEY等）
- ✅ **`.env`**: `.env.shared`へのシンボリックリンク（一元管理）
- ✅ **`.env.local`**: worktree固有の設定（ポート番号等）
- ✅ **MyVaultのDB共有**: 全worktreeで同じマスターキーが必要

**ポイント**:
- `.env.local`は`setup-worktree.sh`が自動生成
- worktree間でポート競合を回避
- `WORKTREE_INDEX`により一貫したポート割り当て
- **マスターキーは全worktreeで統一**（MyVaultのDB共有のため必須）

## 🔐 必須環境変数

### 基本要件

| 変数名 | 必須 | 説明 | 設定方針 |
|--------|------|------|----------|
| `MSA_MASTER_KEY` | ✅ | MyVault暗号化マスターキー | **開発環境**: 固定値使用<br>**本番/ステージング**: 環境ごとに生成 |
| `MYVAULT_SERVICE_TOKEN` | 条件付き | MyVault認証トークン（MYVAULT_ENABLED=true時） | 開発環境では固定値 |

### 開発環境のマスターキー設定方針

**重要**: 開発環境では、全worktreeで**同一のマスターキー**を使用します。

#### なぜ統一が必要か？

MyVaultのデータベースを全worktreeで共有するため、**同じマスターキーでなければ復号化できません**。

```
main worktreeで登録 (キーAで暗号化):
  OPENAI_API_KEY → 暗号化 → DBに保存

feature worktreeで取得 (同じキーAで復号化):
  DBから取得 → 復号化 → OPENAI_API_KEY ✅

feature worktreeで取得 (異なるキーBで復号化):
  DBから取得 → 復号化失敗 ❌ "Failed to decrypt secret"
```

#### 開発環境の固定マスターキー

```bash
# 開発環境共通（全worktreeで使用）
MSA_MASTER_KEY=base64:Rup6PTJHFJybCSG0sY9a/wtT/wNoEWlu1MfV6nCdhr8=
```

**設定場所**: `MySwiftAgent-worktrees/.env.shared`

#### 環境別のキー管理

| 環境 | マスターキー | 管理方法 |
|------|------------|---------|
| **開発環境** | 固定値（全worktree共通） | `.env.shared`で一元管理 |
| **ステージング** | 独自に生成 | 環境変数/シークレット管理ツール |
| **本番環境** | 独自に生成（最重要） | AWS Secrets Manager等 |

## 🚀 使用方法

### 1. 基本的な起動

```bash
# .envと.env.localを読み込んで全サービスを起動
./scripts/unified-start.sh start
```

**内部動作**:
1. `.env`を読み込み
2. `.env.local`を読み込み（優先）
3. サービスURLを自動構成
4. 必須変数をバリデーション
5. サービスを起動

## 🔧 サービスURL自動構成

環境変数ローダーは、以下のサービスURLを自動的に構成します：

| 環境変数 | デフォルト値 | 説明 |
|----------|-------------|------|
| `MYVAULT_BASE_URL` | `http://localhost:${MYVAULT_PORT}` | MyVault APIエンドポイント |
| `JOBQUEUE_API_URL` | `http://localhost:${JOBQUEUE_PORT}` | JobQueue APIエンドポイント |
| `MYSCHEDULER_BASE_URL` | `http://localhost:${MYSCHEDULER_PORT}` | MyScheduler APIエンドポイント |
| `EXPERTAGENT_BASE_URL` | `http://localhost:${EXPERTAGENT_PORT}` | ExpertAgent APIエンドポイント |
| `GRAPHAISERVER_BASE_URL` | `http://localhost:${GRAPHAI_PORT}` | GraphAiServer APIエンドポイント |
| `MYAGENTDESK_BASE_URL` | `http://localhost:${VITE_PORT}` | MyAgentDesk WebUI |
| `COMMONUI_BASE_URL` | `http://localhost:${COMMONUI_PORT}` | CommonUI |

**ポイント**:
- ポート番号は`.env.local`から自動取得
- 既に設定されている場合は上書きしない
- Docker環境では`BASE_HOST`変数でホスト名を変更可能

## ✅ バリデーション機能

### 起動時の自動チェック

スクリプトは以下のチェックを実行します：

1. **必須変数の存在確認**
   ```
   ✓ MSA_MASTER_KEY is set
   ✓ MYVAULT_SERVICE_TOKEN is set (if MYVAULT_ENABLED=true)
   ```

2. **エラー時の動作**
   ```bash
   ERROR: Missing required variable: MSA_MASTER_KEY
   ERROR: Validation failed: 1 required variable(s) missing
   ```

### バリデーションエラーの対処

**エラー例**:
```
[ENV-LOADER] ERROR: Missing required variable: MSA_MASTER_KEY
[ENV-LOADER] ERROR: Validation failed: 1 required variable(s) missing
```

**対処方法**:
1. `.env`ファイルに`MSA_MASTER_KEY`を追加
2. 以下のコマンドで生成：
   ```bash
   python -c "import secrets, base64; print('base64:' + base64.b64encode(secrets.token_bytes(32)).decode())"
   ```
3. 生成されたキーを`.env`に追加：
   ```bash
   MSA_MASTER_KEY=base64:generated_key_here
   ```

## 🔍 トラブルシューティング

### 問題1: ポート競合エラー

**症状**:
```
ERROR: Port 8001 is already in use
```

**原因**: 別のworktreeまたはプロセスが同じポートを使用

**解決策**:
```bash
# 1. 他のworktreeのサービスを停止
cd ../main
./scripts/unified-start.sh stop

# 2. または、.env.localでポート番号を変更
echo "JOBQUEUE_PORT=9001" >> .env.local
```

### 問題2: 環境変数が反映されない

**症状**: `.env`を編集したが変更が反映されない

**原因**: `.env.local`またはカスタムファイルが優先されている

**解決策**:
```bash
# 1. Dry-runで優先順位を確認
./scripts/unified-start.sh start --dry-run

# 2. どのファイルから読み込まれているか確認
# 出力に "from: .env.local" と表示される場合は .env.local を編集

# 3. .env.localを削除して.envのみ使用
rm .env.local
./scripts/unified-start.sh start
```

### 問題3: バリデーションエラー

**症状**:
```
ERROR: Missing required variable: MSA_MASTER_KEY
```

**原因**: 必須変数が設定されていない

**解決策**:
```bash
# 1. .env.exampleをコピー
cp .env.example .env

# 2. マスターキーを生成
python -c "import secrets, base64; print('base64:' + base64.b64encode(secrets.token_bytes(32)).decode())"

# 3. .envに追加
echo "MSA_MASTER_KEY=base64:your_generated_key" >> .env

# 4. 再度起動
./scripts/unified-start.sh start
```

### 問題4: Worktreeでポートが正しく割り当てられない

**症状**: 異なるworktreeなのに同じポートが使用される

**原因**: `.env.local`が正しく生成されていない

**解決策**:
```bash
# 1. .env.localを削除
rm .env.local

# 2. setup-worktreeスキルを実行して再生成
# または手動で作成：
cat > .env.local << EOF
WORKTREE_INDEX=7
MYVAULT_PORT=8173
JOBQUEUE_PORT=8171
MYSCHEDULER_PORT=8172
EXPERTAGENT_PORT=8174
GRAPHAI_PORT=8170
VITE_PORT=5180
EOF

# 3. 再度起動
./scripts/unified-start.sh start
```

## 🎓 ベストプラクティス

### 開発環境での推奨設定

#### 1. 共通設定ファイルの使用（推奨）

```bash
# MySwiftAgent-worktrees/.env.shared を作成
cd /path/to/MySwiftAgent-worktrees

cat > .env.shared << 'EOF'
# 開発環境共通設定
MSA_MASTER_KEY=base64:Rup6PTJHFJybCSG0sY9a/wtT/wNoEWlu1MfV6nCdhr8=
MYVAULT_ENABLED=true
MYVAULT_SERVICE_TOKEN=OboWWxpr90ytHQrLqbY-Cur3s-EPojbZ
# ... その他の共通設定
EOF

# 各worktreeからシンボリックリンク
cd main
ln -s ../.env.shared .env

cd ../feature-xxx
ln -s ../.env.shared .env
```

**メリット**:
- ✅ マスターキーの一元管理
- ✅ 全worktreeで設定の一貫性保証
- ✅ キー変更が1回で済む

#### 2. worktree固有設定は`.env.local`のみ

```bash
# .env.local（worktree固有）
WORKTREE_INDEX=7
MYVAULT_PORT=8173
JOBQUEUE_PORT=8171
MYSCHEDULER_PORT=8172
EXPERTAGENT_PORT=8174
LOG_LEVEL=DEBUG  # このworktreeのみDEBUG
```

#### 3. `.env`ファイルのバージョン管理

```bash
# .gitignoreに追加（既に設定済み）
.env
.env.local
.env.shared
.env.production
.env.staging
```

#### 4. dry-runの活用

```bash
# 設定確認後に起動
./scripts/unified-start.sh start --dry-run && \
./scripts/unified-start.sh start
```

#### 5. カスタムファイルの命名規則

```
.env.shared      # 開発環境共通設定（全worktree）

```

