## 3. 改善提案

### 3.1 AC-4（E2Eテストの動的スキーマ取得）のテスト項目をより具体的に

**現状**: TC-008は「スキーマ取得ログを確認」「動的ペイロード構築を確認」とあるが、具体的な検証方法（例: ログ出力の期待値）が不足

**提案**: 以下の検証ポイントを追加

```
- ログに「Keyword field: XXX」「Email field: XXX」が出力される
- 生成されたペイロードがスキーマのpropertiesキーと一致する
```

### 3.2 LLMが異なるフィールド名を生成した場合のテストシナリオ追加

**現状**: TC-008に「LLMが異なるフィールド名を生成しても成功する」とあるが、具体的なテストケースがない

**提案**: 以下のテストケースを追加

```markdown
### TC-011: LLM生成フィールド名の変動対応テスト
- **テスト観点**: LLMが email_recipient や search_query 等を生成した場合の動作確認
- **関連する受入条件**: AC-4
- **テスト種別**: E2E
- **検証方法**: 異なるプロンプトでJob生成を複数回実行し、フィールド名が異なっても成功することを確認
- **期待結果**: フィールド名のバリエーションに関わらずテストが成功
```

### 3.3 myAgentDesk単体テストのカバレッジ測定コマンドが不足

**現状**: Phase 3のmyAgentDeskテストにカバレッジ測定コマンドがない

**提案**: 以下を追加

```bash
npm run test:unit -- --coverage
```

### 3.4 マイグレーション失敗時のロールバックテスト項目がない

**現状**: 設計方針書（11.2）に詳細なロールバック手順があるが、それを検証するテスト項目がない

**提案**: 以下のテストケースを追加

```markdown
### TC-012: マイグレーションロールバック検証
- **テスト観点**: マイグレーション適用後にロールバック可能なことを確認
- **関連する設計方針**: DP-4
- **テスト種別**: 手動検証
- **テスト手順**:
  1. マイグレーション適用
  2. データ挿入
  3. ロールバック実行
  4. 既存機能が正常動作することを確認
- **期待結果**: ロールバック後も既存機能が正常動作
```

### 3.5 CI-1（user_input_schemaとinterface_definitionsの整合性）の検証タイミングが不明確

**現状**: セクション9で確認項目がチェックリストとして記載されているが、いつ・誰が検証するか不明

**提案**: 「Phase 5: E2Eテスト」の前に「Phase 4.5: コンポーネント間整合性レビュー」を追加

### 3.6 OpenAPI仕様検証のテスト項目追加

**現状**: F-2で「OpenAPI仕様に`user_input_schema`フィールドが含まれることを確認」とあるが、独立したテストケースがない

**提案**: TC-003の検証に以下を追加

```bash
# OpenAPI仕様確認
curl -s http://localhost:8004/openapi.json | jq '.components.schemas.JobGeneratorResponse.properties.user_input_schema'
```
