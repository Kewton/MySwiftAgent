# 要件定義書: 受入テストの効率化

## 1. プロジェクト概要

**Issue番号**: #140
**タイトル**: 受入テストの効率化
**目的**: MySwiftAgentの受入テストプロセスを効率化するため、全マイクロサービスの一括起動とworktree並列テスト環境を提供する

## 2. ユーザーストーリー

### 2.1 主要ストーリー

1. **As a** Product Owner (PO)
   **I want to** 一つのスクリプトで全てのマイクロサービスを起動できる
   **So that** 受入テストの開始時間を短縮し、テスト効率を向上できる

2. **As a** Product Owner (PO)
   **I want to** 複数のブランチで同時に全サービスを起動してテストできる
   **So that** 並行して複数の機能の受入テストを実施でき、リリース速度を向上できる

### 2.2 補助ストーリー

3. **As a** QA Engineer
   **I want to** 各サービスの起動状態とヘルスチェック結果を一括確認できる
   **So that** テスト環境の問題を迅速に特定・解決できる

4. **As a** Developer
   **I want to** 起動エラー時の詳細なログとトラブルシューティング情報を取得できる
   **So that** 環境構築の問題を自己解決できる

## 3. ビジネス価値

### 3.1 定量的価値
- **セットアップ時間の短縮**: 個別起動（10-15分）→ 一括起動（2-3分）で約80%削減
- **並列テスト実施**: 最大4ブランチでの同時テストによりテストサイクルを75%短縮
- **エラー解決時間**: トラブルシューティング機能により環境問題解決時間を50%削減

### 3.2 定性的価値
- テスターの認知負荷軽減（複数コマンドの記憶不要）
- テスト環境の再現性向上（標準化された起動手順）
- 開発者とQA間のコミュニケーションコスト削減

## 4. 機能要件

### 4.1 一括起動機能

#### 4.1.1 サービス起動管理
- **全サービス一括起動**: 単一コマンドで以下のサービスを順次起動
  - jobqueue (Port: 8101)
  - myscheduler (Port: 8102)
  - myVault (Port: 8103)
  - expertAgent (Port: 8104)
  - graphAiServer (Port: 8105)
  - myAgentDesk (Port: 5173)
  - commonUI (Port: 8601)

#### 4.1.2 起動順序制御
```
1. インフラサービス層
   ├── myVault (シークレット管理)
   └── jobqueue (キュー管理)
2. ミドルウェア層
   ├── myscheduler (ジョブスケジューリング)
   └── graphAiServer (ワークフロー実行)
3. アプリケーション層
   ├── expertAgent (AIエージェント)
   └── myAgentDesk/commonUI (UI)
```

#### 4.1.3 環境変数管理
- プロジェクトレベル `.env` ファイルの自動読み込み
- worktree固有 `.env.local` の優先適用
- サービスURL自動構成（JOBQUEUE_API_URL等）

### 4.2 Worktree並列起動機能

#### 4.2.1 ポート番号自動割り当て
- 空きインデックス検出アルゴリズム
- インデックス基準のポート番号計算（base_port + index × 10）
- ポート衝突の自動回避

#### 4.2.2 リソース分離戦略
| リソース | 共有モード | 独立モード | カスタムモード |
|---------|-----------|-----------|--------------|
| myVault DB | developブランチと共有 | worktree毎に独立DB | 任意パスを指定 |
| langfuse | Docker単一インスタンス | worktree毎にDocker | 指定パスと共有 |
| ログファイル | - | worktree毎に独立 | - |
| 仮想環境 | - | worktree毎に独立 | - |

### 4.3 ヘルスチェック機能

#### 4.3.1 起動時ヘルスチェック
- 各サービスの `/health` エンドポイント監視
- タイムアウト設定（デフォルト30秒、設定可能）
- リトライ機構（1秒間隔）

#### 4.3.2 ステータス監視
```bash
# コマンド例
./scripts/unified-start.sh status

# 出力例
✅ JobQueue: Running healthy (PID: 12345, Port: 8101)
✅ MyScheduler: Running healthy (PID: 12346, Port: 8102)
⚠️ MyVault: Running but health check failed (PID: 12347, Port: 8103)
❌ ExpertAgent: Not running
```

### 4.4 エラーハンドリング

#### 4.4.1 起動失敗時の処理
- 依存サービスの起動確認
- ポート競合の自動解決（既存プロセスの停止オプション）
- 詳細なエラーログ出力

#### 4.4.2 ロールバック機能
- 部分的な起動失敗時の自動停止
- クリーンアップ処理（PIDファイル、一時ファイル削除）

## 5. 非機能要件

### 5.1 パフォーマンス
- **起動時間**: 全サービス起動完了まで3分以内
- **並列起動**: 最大4 worktreeの同時起動対応
- **リソース使用**: メモリ使用量8GB以下（1 worktreeあたり）

### 5.2 信頼性
- **起動成功率**: 95%以上（適切な環境設定時）
- **エラー検出**: 100%のサービス起動失敗を検出
- **自動復旧**: ポート競合の80%を自動解決

### 5.3 保守性
- **設定ファイル**: YAML/TOML形式での設定管理
- **ログ管理**: サービス別・worktree別のログ分離
- **バージョン管理**: スクリプトバージョニングとの後方互換性

### 5.4 ユーザビリティ
- **コマンド体系**: 直感的なサブコマンド（start/stop/restart/status/logs）
- **進捗表示**: カラフルな出力とプログレスインジケータ
- **ヘルプ機能**: `--help` オプションでの詳細説明

## 7. 制約条件

### 7.1 技術的制約
- **OS**: macOS/Linux（Windows WSL2対応）
- **依存ツール**:
  - uv (Python package manager)
  - npm/node (v18以上)
  - Docker (langfuse使用時)
  - git (worktree機能)
- **Python**: 3.11以上
- **ディスク容量**: 10GB以上の空き容量（worktreeあたり）

### 7.2 運用的制約
- 同一マシンでの最大並列worktree数: 4
- myVault使用時はマスターキー設定が必須
- Docker Desktop起動が前提（langfuse使用時）

## 8. 前提条件

### 8.1 環境準備
- [ ] リポジトリのクローン完了
- [ ] `.env` ファイルの作成（`.env.example` から複製）
- [ ] 必要なAPIキーの設定完了
- [ ] Docker Desktopのインストールと起動（オプション）

### 8.2 権限要件
- ポート8100-8200、5173-5180へのbind権限
- ログディレクトリへの書き込み権限
- プロセス管理権限（kill, pkill）

### 9.1 スクリプト実装
- **言語**: Bash (POSIX準拠)
- **構成管理**: YAML/TOML（将来的な拡張）
- **プロセス管理**: systemd/supervisord（本番環境）

### 9.2 統合スクリプトの構成
```bash

├── unified-start.sh      # 新規: 統一起動スクリプト
├── config/
│   ├── services.yaml     # サービス定義
│   └── dependencies.yaml # 依存関係定義

    └── env.template       # 環境変数テンプレート
```

### 9.3 既存資産の活用
